Gateway model names

Какие имена моделей использовать

Во всех запросах указывайте gateway-имя модели из каталога ниже. Это не обязательно совпадает с именем модели у провайдера. Каталог строится из текущей конфигурации gateway и не делает внешних запросов.

Reranker

Rerank: параметры вызова

POST /v1/rerank

Используйте rerank, когда нужно отсортировать документы по релевантности к запросу.

modelобязательноGateway-модель из группы Rerank в каталоге.
queryобязательноЗапрос, относительно которого ранжируются документы.
documentsобязательноМассив строк с документами-кандидатами.
top_nопциональноСколько лучших результатов вернуть. Если не задано, возвращается весь список.
return_documentsопциональноЕсли true, в ответ добавляется текст исходного документа.
Ответdata[] с index, score и, если просили, document.
 
curl -s /rerank \
  -H "Authorization: Bearer $GATEWAY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "llmgateway/rerank",
    "query": "документ про маршрутизацию моделей",
    "documents": [
      "Gateway models are called through a single API.",
      "Images are generated through /v1/images/generations.",
      "Usage statistics are grouped by day and month."
    ],
    "top_n": 2,
    "return_documents": true
  }'

В отдельных конфигурациях ответ может быть в Jina-совместимом поле results[].

Documents

PDF conversion

POST /v1/pdf/convert

Content-TypeобязательноИспользуйте multipart/form-data.
fileобязательноPDF-файл для конвертации.
modelобязательноGateway-модель из группы PDF conversion.
outputопциональноФормат результата: both, docx или md. По умолчанию используйте both, если нужны оба файла.
languageопциональноЯзыки OCR в формате converter-сервиса, например rus+eng.
target_languageопциональноЯзык перевода итогового Markdown перед сборкой DOCX/MD, например English или Russian. Пустое поле или отсутствие параметра означает без перевода.
math_ocr_providerопциональноПровайдер распознавания формул: off, mathpix или local_im2latex.
formulas_max_pagesопциональноМаксимум страниц для распознавания формул. Пустое поле означает авто/дефолт сервиса.
max_pagesопциональноОграничение количества страниц для обработки, удобно для тестового прогона.
passwordопциональноПароль для защищённого PDF.
ocr_preprocess_saveопциональноЕсли true, converter должен сохранить preprocessed PDF как отдельный артефакт для отладки OCR.
ОтветСинхронный JSON converter-сервиса. Для долгих файлов предпочтительнее async job API.

PDF jobs

POST /v1/pdf/jobsСоздаёт async job; принимает те же multipart-поля, что и /v1/pdf/convert. Playground использует именно этот endpoint.
GET /v1/pdf/jobs/{job_id}Статус job. Передайте model в query string; ответ может содержать progress, eta_seconds, message и список events[].
GET /v1/pdf/jobs/{job_id}/resultИтоговый JSON job. Передайте model в query string; в результате ожидаются артефакты docx, md и при включённом debug-флаге preprocessed-pdf.
GET /v1/pdf/jobs/{job_id}/download/{artifact}Скачивание артефакта, например docx, md или preprocessed-pdf. Передайте model в query string.

Async job example

curl -s /pdf/jobs \
  -H "Authorization: Bearer $GATEWAY_API_KEY" \
  -F "model=llmgateway/pdf-converter" \
  -F "file=@document.pdf;type=application/pdf" \
  -F "output=both" \
  -F "language=rus+eng" \
  -F "target_language=English" \
  -F "math_ocr_provider=mathpix" \
  -F "formulas_max_pages=10" \
  -F "max_pages=47" \
  -F "ocr_preprocess_save=true"

После завершения скачивайте файлы через /v1/pdf/jobs/{job_id}/download/{artifact}?model=llmgateway/pdf-converter.

web*

Web-сервисы: параметры вызова

POST /v1/web/search

modelобязательноGateway-модель, настроенная для web search.
queryобязательноПоисковый запрос пользователя.
max_resultsопциональноСколько поисковых результатов вернуть. Диапазон: 1-20, по умолчанию 10.
num_queriesопциональноСколько поисковых запросов выполнить для одной темы. Диапазон: 1-5, по умолчанию 1.
languageопциональноЯзык поиска. По умолчанию ru.
include_raw_contentопциональноTavily-compatible флаг. Если true, markdown или text, gateway скачивает найденные страницы через локальный read pipeline и добавляет raw_content в каждый элемент data[].
read_modelопциональноGateway-модель из web_read для скачивания raw_content. Нужна, если включён include_raw_content и в конфигурации есть несколько read-моделей.
include_domainsопциональноTavily-compatible список доменов, которые нужно оставить в результатах. Можно передать массив строк или строку через запятую.
exclude_domainsопциональноTavily-compatible список доменов, которые нужно убрать из результатов. Можно передать массив строк или строку через запятую.
include_imagesопциональноTavily-compatible флаг. Если true, каждый элемент data[] получает поле images[]. Gateway не выполняет отдельный image search; если pipeline не извлёк картинки, массив будет пустым.
Ответdata[] с найденными страницами и usage с расходом запроса. При включённых флагах элементы могут содержать raw_content и images[].

POST /v1/web/read

modelобязательноGateway-модель, настроенная для чтения веб-страниц.
urlобязательноАдрес страницы, которую нужно загрузить и извлечь в текст.
formatопциональноФормат результата: markdown или text. По умолчанию markdown.
include_imagesопциональноЕсли true, ответ дополнительно содержит images[]. Если pipeline не извлёк картинки, массив будет пустым.
Ответurl, title, извлечённый content, usage и опционально images[].

POST /v1/tavily/search

queryобязательноПоисковый запрос в Tavily-compatible формате.
modelопциональноGateway-модель из web_search. Если она одна, gateway выберет её автоматически.
max_resultsопциональноСколько результатов вернуть. Диапазон: 1-20, по умолчанию 5.
include_raw_contentопциональноЕсли включено, каждый элемент results[] получает raw_content через gateway read pipeline.
read_modelопциональноGateway-модель из web_read для raw_content. Нужна при нескольких read-моделях.
include_domainsопциональноСписок доменов, которые нужно оставить в результатах.
exclude_domainsопциональноСписок доменов, которые нужно убрать из результатов.
include_imagesопциональноЕсли true, Tavily-format ответ содержит top-level images[] и images[] внутри каждого результата. Без извлечённых картинок массивы пустые.
ОтветTavily-compatible объект с results[], failed_results[], answer, images[], response_time, usage и request_id.

POST /v1/tavily/extract

urlsобязательноОдин URL строкой или массив URL, которые нужно скачать через gateway read pipeline.
modelопциональноGateway-модель из web_read. Если она одна, gateway выберет её автоматически.
formatопциональноФормат извлечённого контента: markdown или text. По умолчанию markdown.
extract_depthопциональноПринимается для совместимости с Tavily-клиентами; скачивание выполняет gateway read pipeline.
include_imagesопциональноЕсли true, каждый элемент results[] содержит images[]. Если pipeline не извлёк картинки, массив будет пустым.
ОтветTavily-compatible объект с results[], failed_results[], images[] внутри результатов, response_time, usage и request_id.

POST /v1/web/research

modelобязательноGateway-модель, настроенная для обычного web research.
queryобязательноТема исследования или вопрос, по которому нужно собрать источники.
languageопциональноГде искать источники: all, ru, en, zh или список через запятую. По умолчанию all.
num_queriesопциональноСколько поисковых запросов построить для темы. Диапазон: 1-5.
max_results_per_langопциональноСколько результатов брать на каждый язык поиска. Диапазон: 1-20, по умолчанию 10.
max_resultsопциональноАльтернативное имя общего лимита результатов, если не используется max_results_per_lang.
max_articlesопциональноСколько найденных материалов читать и использовать в отчёте. Диапазон: 1-10, по умолчанию 8.
output_languageопциональноЯзык итогового отчёта. По умолчанию ru.
formatопциональноФормат итогового отчёта. По умолчанию markdown.
Ответoutput с отчётом, sources, прочитанные articles и usage.

POST /v1/web/deep-research

modelобязательноGateway-модель, настроенная для deep research.
queryобязательноСложный вопрос или тема, по которой нужен многошаговый исследовательский отчёт.
max_wordsопциональноОграничивает длину итогового отчёта. Диапазон: 200-8000, по умолчанию 2500.
breadthопциональноШирина исследования: сколько направлений искать на каждом шаге. Диапазон: 1-10, по умолчанию 4.
depthопциональноГлубина исследования: сколько итераций поиска и анализа выполнить. Диапазон: 1-5, по умолчанию 2.
concurrencyопциональноСколько операций выполнять параллельно. Диапазон: 1-10, по умолчанию 6.
languageопциональноЯзык итогового отчёта. По умолчанию ru.
formatопциональноФормат итогового отчёта. По умолчанию markdown.
image_generationопциональноЕсли true, deep research дополнительно запрашивает изображения и возвращает их в images[]. По умолчанию false.
Ответoutput с отчётом, sources, source_urls, рабочий context, images и usage.

Admin testing

Playground

Master-админ может открыть /v1/ui/playground, чтобы вручную проверить текущие operation routes без отдельного клиента. Старый путь /v1/ui/web-playground сохранён как alias.

Разделы

Web/v1/web/search, /v1/web/read, Tavily-compatible routes, research и deep research.
Speech to TextPOST /v1/audio/transcriptions через multipart/form-data, выбор языка/формата и скачивание результата.
Text to SpeechGET /v1/audio/voices для голосов выбранной модели, затем POST /v1/audio/speech; ответ проигрывается и скачивается как audio-файл.
Images/v1/images/generations и /v1/images/edits; есть выбор размера, preview результата и скачивание изображений, editing принимает до 4 файлов image[].
PDFPOST /v1/pdf/jobs с PDF-файлом, выбранной gateway-моделью, output=both|docx|md, language, опциональным target_language для перевода, настройками OCR/formula OCR, паролем и флагом ocr_preprocess_save; результат скачивается через job download endpoints.

Access control

Доступ virtual keys

Виртуальный ключ lgk_... вызывает API так же, как master-key. Если для него задан allowed_models, можно вызывать только перечисленные gateway-модели. Для web_research и web_deep_research проверяется только сервисная модель из поля model. Если поиск запрашивает include_raw_content, дополнительно проверяется доступ к выбранной read_model, потому что скачивание страниц выполняет отдельный read-сервис. Для PDF job status/result/download модель передаётся в query string и проверяется так же, как при создании job.
